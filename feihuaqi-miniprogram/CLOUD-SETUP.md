# 云开发联调手册

> 面向操作者。云函数代码已在本地用内存替身验证（22 项断言），
> 本手册负责把它真正跑起来。
> 生成时间：2026-10-09

---

## 一、前置

1. `project.config.json` 里的 `appid` 换成真实小程序 AppID（当前是 `touristappid` 占位）。
2. 开发者工具中开通云开发，创建一个环境（记下环境 ID）。
3. 云函数会用到当前环境，无需在代码里硬编码环境 ID —— 四处 `cloud.init` 都用的是
   `cloud.DYNAMIC_CURRENT_ENV`，即自动取当前环境。

---

## 二、部署云函数

四个函数，逐个右键 →「上传并部署：云端安装依赖」：

| 函数 | 作用 | 触发时机 |
|---|---|---|
| `authLogin` | 静默登录 + 建档 | App 启动 |
| `submitScore` | 分数提交 + 榜单更新 | 对局结算 |
| `getRank` | 榜单读取 | 打开榜单页 |
| `trackChannel` | 渠道归因 | 主菜单加载 |

> 依赖只有 `wx-server-sdk`，云端安装即可。

---

## 三、集合：不需要手动创建

云开发不会自动创建集合，首次访问不存在的集合会抛 `-502005`。
四个云函数都已内置自愈：捕获该错误 → 补建全部集合 → 重试一次。

需要的集合共 5 个：

| 集合 | 用途 |
|---|---|
| `users` | openid、昵称、名号、渠道、最佳分数 |
| `runs` | 每一局明细，用于防刷对账与幂等 |
| `leaderboard` | 每人一条最好成绩 |
| `channelDaily` | 渠道的日粒度 PV / UV |
| `channelVisits` | 当日访客去重，用于算 UV |

首次进入小程序后，控制台里应能看到这五个集合自动出现。

**如果希望手动创建**（例如想先设好权限），在控制台建同名集合即可，自愈逻辑会跳过已存在的。

---

## 四、建议手动加的索引

自愈能建集合，但建不了索引。数据量上来后没有索引的榜单会明显变慢：

| 集合 | 字段 | 类型 |
|---|---|---|
| `leaderboard` | `score` | 降序 |
| `leaderboard` | `openid` | 升序（唯一） |
| `runs` | `openid` + `runId` | 组合索引 |
| `users` | `openid` | 升序（唯一） |
| `channelVisits` | `date` | 升序 |

`leaderboard.openid` 建唯一索引后，即使并发提交也不会出现同一人多行。

---

## 五、集合权限

榜单是公开数据，但写入必须走云函数（云函数拥有管理权限，不受集合权限限制）。
建议设为：

| 集合 | 权限 |
|---|---|
| `leaderboard` | 仅创建者可读写（客户端本来也不直连） |
| `users` / `runs` / `channelDaily` / `channelVisits` | 仅管理端可读写 |

小程序端全程只调云函数，不直接读写数据库，这样最安全。

---

## 六、可选：与 H5 榜单统一

H5 版榜单跑在 Supabase。云函数出网不受小程序域名白名单限制，
所以由 `submitScore` 双写即可保持两端一致（配置环境变量）：

| 变量 | 值 |
|---|---|
| `SUPABASE_SYNC` | `1` 开启双写，留空或 `0` 关闭 |
| `SUPABASE_URL` | Supabase 项目地址，如 `https://xxxx.supabase.co` |
| `SUPABASE_ANON_KEY` | 项目的 anon key |

**注意**：小程序前端**不能**直连 Supabase —— `request` 合法域名必须 ICP 备案，
`supabase.co` 无法加入白名单。这也是必须走云函数中转的原因。

双写失败不会影响小程序侧写入（已做隔离）。

## 七、端到端验证清单

在开发者工具或真机上依次确认：

- [ ] **启动即建档**：打开小程序 → 控制台 `users` 集合出现一条记录，`channel` 字段与进入方式相符
- [ ] **完成一局**：跑到结算 → `runs` 出现一局明细、`leaderboard` 出现本人一行
- [ ] **榜单可读**：主菜单进榜单 → 能看到自己，名次与分数正确
- [ ] **名次正确**：用两个账号分别提交不同分数 → 高分者名次更靠前
- [ ] **离线降级**：断网后进榜单 → 显示「榜单读取失败，可下拉重试」而不是白屏
- [ ] **云未开通时**：关闭云环境 → 进榜单显示「云环境尚未开通」，且**单机玩法完全不受影响**
- [ ] **渠道归因**：用分享卡片进入 → `channelDaily` 的 `count` 递增
- [ ] **存档不受影响**：对局中杀进程 → 重新进入可「继续游戏」

## 八、常见错误对照

| 现象 | 原因 | 处理 |
|---|---|---|
| `-502005 collection not exists` | 集合不存在（自愈未生效或函数未更新） | 重新上传云函数；或手动建集合 |
| `-502003 permission denied` | 客户端直连了数据库 | 确认只走云函数，不写 `wx.cloud.database()` |
| `cloud.init` 报错 / `NO_CLOUD_ENV` | 未开通云开发或环境未选 | 工具中开通并选择环境 |
| 榜单名次明显偏小 | `leaderboard` 缺 `score` 索引 | 按第四节建索引 |
| `submitScore` 一直返回 429 | 10 秒内重复提交 | 正常防刷；测试时可传 `force: true` |
| 分数提交返回 400 | 分值非法或时长 < 30 秒 | 正常校验；真人对局不会触发 |

---

## 九、上线前要清掉的东西

- `submitScore` 的 `force` 参数是为联调保留的跳过频控开关，**上线前应移除或加环境判断**
- `appid` 确认为正式 AppID，不要带着 `touristappid` 上传
- 确认「不校验合法域名」等调试选项已关闭
