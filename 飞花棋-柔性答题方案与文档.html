飞花棋 · 柔性答题（情境化选择）方案与交接文档

目标：把「知识考课」里的显式 ABCD 问答，改成情境中的行动选择——本质仍是做题、判定机制不变，只是玩家看到的是「你身处某刻、想做某件事」，而非「A 张继 B 李白 C 杜甫」。
范围：仅改造 type:"knowledge" 题目的展示文案；引擎判定、数值奖励、答题倒计时全部保持不变。
状态：本文件为方案与交接文档，不含代码改动。执行窗口据此落地。

---

一、任务概述

用户原话示例：

枫桥夜泊的作者是（）A 张继 B 李白 C 杜甫。
改后：你旅至枫桥，于此夜泊，忽闻寒山寺传来钟声，你心有所感，打算诵上一句古人诗句。第一选择念张继的诗，第二念李白的，第三念杜甫的……

核心诉求：

1. 保留「做题」内核——题目事实、正误判定、属性/灵感奖惩都不变。

2. 去掉直白的「A/B/C/D + 选项原文」，换成「情境 + 你会做什么」的柔性选择。

3. 文档要能直接交给另一个对话窗口执行，因此需给出字段规范、改写范式、完整示例、最小代码改动点、验收标准。

---

二、现状与可行性（为什么改动很小）

现有答题链路（实际可玩构建 feihuaqi-playable/）：

  • 出题：js/engine/game.js doQuiz() —— 70% 抽 knowledge、30% 抽 choice；判定仅一行：const ok = !ans.timedOut && ans.index === q.answer;
  • 展示：js/ui/modals.js showQuiz(q) —— 渲染 q.stem 为题面，选项渲染为 <span class="idx">A</span> 选项原文，点击回传 index。
  • 结果：showQuizResult(q, ans, ok) —— 用 q.answer 高亮正确项，答错时显示 正确答案：A．张继。

    • 关键结论：判定是纯索引式。options 数组的顺序就是答案，answer 只是下标。只要：

  • 选项数组顺序不变；
  • 新增的「情境文案」「选项动作文案」与原 options 顺序一一对应；

    • 引擎 game.js 与 config.js 一行都不用改，只动 modals.js 的展示逻辑。这是低风险改造。

    题库概况：config/questions.json 共 67 题，其中 knowledge 49、choice 18；类别 shi 23、ci 16、lian 13、mix 15。本文只处理 knowledge 49 题；choice（创作抉择）保持原样。

    三、内容模型（目标字段规范）

    在现有 knowledge 题目上增量新增两个可选字段，不改动原有字段，保证向后兼容：

    {
  "id": "Q0001",
  "type": "knowledge",
  "stem": "「夜半钟声到客船」的作者是？",
  "scenario": "你旅至枫桥，于此夜泊。夜半，寒山寺钟声悠悠传来，惊起岸边宿鸟。你披衣坐起，忽有所感，便想向同舟的旅人诵一句古人的诗，以寄此刻羁旅之意。",
  "options": ["张继", "杜牧", "李白", "王维"],
  "optionActs": [
    "诵张继《枫桥夜泊》：「月落乌啼霜满天，江枫渔火对愁眠」",
    "诵杜牧《泊秦淮》：「烟笼寒水月笼沙，夜泊秦淮近酒家」",
    "诵李白《静夜思》：「床前明月光，疑是地上霜」",
    "诵王维《山居秋暝》：「空山新雨后，天气晚来秋」"
  ],
  "answer": 0,
  "analysis": "答案是张继。此句是《枫桥夜泊》末句……",
  "enabled": true
}

    字段约定：

    字段是否改动作用
    stem保留机器/编辑参考用的原题面；scenario 存在时界面不显示它
    scenario新增（可选）情境化题面，替换 stem 的展示
    options保留答案身份数组（张继/杜牧/…），顺序即判定，不可打乱
    optionActs新增（可选）与 options 等长、同序；玩家点击时看到的「动作文案」
    answer保留正确项下标，指向 options/optionActs 同一位置
    analysis保留答后解析，原样展示即可（解释的是事实，与包装无关）

    兼容规则：scenario/optionActs 缺省时，modals.js 退化为当前渲染（显示 stem + options 原文 + ABCD 角标），旧题零影响。

    四、题型转换范式（改写 cheat sheet）

    knowledge 题可归为几类「提问原型」。每类给一个情境模板和选项动作写法规则，内容作者照此批量产出即可。

    原型示例原题情境落点选项动作写法
    作者是谁「夜半钟声…」作者？把人带到诗发生的地点/时刻，想「诵/评」一句「诵{诗人}{代表作}：『名句』」
    词牌/诗体「但愿人长久」词牌？友人赞某词，问你依何调「答：依《{词牌}》——『名句』」
    上一句/下一句「野火烧不尽」下一句？与人联句/教童子，要接下去「接：『{诗句}』」
    对句/下联上联「两个黄鹂…」下联？题联/补对，要凑成工对「补：『{诗句}』」
    写的是哪处「一览众山小」写哪座山？登临某山，同伴问是哪座「答：是{山/地}」
    出自哪首诗「锄禾日当午」出自？评某句，问其来处「道：出自《{诗名}》」
    意象/手法（mix）某手法指什么评点作品，要你点破「说：这是{手法}——『例句中…』」

    通用原则：情境结尾给一个明确意图动词（想诵 / 要答 / 接着背 / 补一句 / 道是哪座），让四个选项自然成为「四种可做之事」。干扰项在情境里都要 plausibly 可做，只是按文学事实错误（换了诗人、换了诗、换了对句）。

    五、完整示例（5 题，跨类别）

    下面 5 题已按规范写好，顺序与 options 严格对齐，answer 下标不变。执行窗口可直接作为首批种子数据。

    示例 1 · 作者是谁（shi）

  • 原题：「夜半钟声到客船」的作者是？
  • scenario：你旅至枫桥，于此夜泊。夜半，寒山寺钟声悠悠传来，惊起岸边宿鸟。你披衣坐起，忽有所感，便想向同舟的旅人诵一句古人的诗，以寄此刻羁旅之意。
  • optionActs：

    • 1. 诵张继《枫桥夜泊》：「月落乌啼霜满天，江枫渔火对愁眠」

    2. 诵杜牧《泊秦淮》：「烟笼寒水月笼沙，夜泊秦淮近酒家」

    3. 诵李白《静夜思》：「床前明月光，疑是地上霜」

    4. 诵王维《山居秋暝》：「空山新雨后，天气晚来秋」

  • answer：0

    • 示例 2 · 词牌（ci）

  • 原题：「但愿人长久，千里共婵娟」的词牌名是？
  • scenario：中秋夜，友人斟酒相劝，叹道：「苏子此词，把人间聚散写尽了。」他望着天上月，问你：这首依的是何调？你略一沉吟，便要答他。
  • optionActs：

    • 1. 答：依《水调歌头》——「明月几时有，把酒问青天」

    2. 答：依《念奴娇》——「大江东去，浪淘尽」

    3. 答：依《西江月》——「明月别枝惊鹊，清风半夜鸣蝉」

    4. 答：依《满江红》——「怒发冲冠，凭栏处」

  • answer：0

    • 示例 3 · 下一句（shi）

  • 原题：「野火烧不尽」的下一句是？
  • scenario：你与童子在古原上送别，望着离离原草。童子仰头问你：「野火烧不尽」之后，该怎么接？你笑着要往下背。
  • optionActs：

    • 1. 接：『春风吹又生』

    2. 接：『一岁一枯荣』

    3. 接：『又送王孙去』

    4. 接：『萋萋满别情』

  • answer：0

    • 示例 4 · 下联（lian）

  • 原题：上联「两个黄鹂鸣翠柳」，下联是？
  • scenario：草堂初成，你在门上题了上联「两个黄鹂鸣翠柳」，想再补一句，与它对仗成趣。访客在旁催促：下句写什么？
  • optionActs：

    • 1. 补：『一行白鹭上青天』

    2. 补：『门泊东吴万里船』

    3. 补：『窗含西岭千秋雪』

    4. 补：『柳暗花明又一村』

  • answer：0

    • 示例 5 · 写的是哪处（shi）

  • 原题：杜甫「会当凌绝顶，一览众山小」写的是哪座山？
  • scenario：你登临一座名山，望见齐鲁大地青峦连绵。同伴道：杜工部写「会当凌绝顶，一览众山小」，说的便是眼前这座——你道是哪座？
  • optionActs：

    • 1. 答：是华山

    2. 答：是庐山

    3. 答：是泰山

    4. 答：是黄山

  • answer：2

    • 注意示例 4 的干扰项 2、3 同出杜诗，但作为「紧接上联的对句」是错误的——这正是题目本意（考对仗位置），情境中仍 plausible，保留即可。

const optTextOf = (o, i) =>

    七、文案写作规范（叙事设计约束）

    1. 统一第二人称「你」；运行时由 personalize() 注入玩家名号，数据文件勿写 {name}。

    2. 情境须落在与题目相关的地点 / 时刻 / 动作上（枫桥→夜泊钟声；中秋→苏词；古原→送别），不可凭空套景。

    3. 每个选项动作必须点出具体诗人 + 作品 + 至少一句名句，使「选哪个」一目了然且彼此可区分。

    4. 干扰项在情境中要 plausibly 可做，但按文学事实错误（换诗人 / 换诗 / 换对句 / 换地）。

    5. 情境结尾给明确意图动词：想诵 / 要答 / 接着背 / 补一句 / 道是哪座。

    6. 不替玩家下结论，不解释「这象征什么」；把余韵留给玩家。

    7. 篇幅：scenario 40–90 字；单条 optionAct 12–30 字。

    8. analysis 原样保留（解释事实），不必改写；若改须保证与 answer 对应。

    十、风险与边界

  • 致命风险：optionActs 与 options 顺序错位 → 判定整题错乱。校验脚本必须卡死「等长 + 下标合法」。
  • 干扰项若诗意牵强会出戏，需编辑把关，不可机器硬凑。
  • choice（创作抉择）本次不碰；若日后也情境化，可复用同一套 scenario 字段。
  • 不改 game.js 是硬约束——任何「让情境影响判定」的念头都会破坏索引判定，必须拒绝。
