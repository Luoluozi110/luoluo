# 文心棋数值系统全面重构方案 v1

日期：2026-09-05

状态：v2 已实施并部署。本文保留为设计与验收规格；实际换算、兼容与回归结果见第 16 节。

范围：单人可玩版及其编辑器、内容同步、存档、跨局成长和评分接口；多人参考实现列为兼容验收对象。

依据：本工作区当前根目录的 `config/`、`js/engine/`、`feihua-content.json` 与编辑器种子。历史设计稿及 Git HEAD 仅用于追溯，不替代实际代码。文中“当前”为文件核查结果，“目标”为本方案决策，“试验”为需要模拟和试玩校准的候选值。

## 1. 决策摘要

采用“六维／灵感／心得十倍尺度，连续进度整数化，骰点和次数保留，战斗分十倍尺度，终局评级保持原量级”的总体结构。重构的价值是获得更细的奖励档位、可解释的资源交换和稳定的结算顺序。

交付分成三个阶段，必须分别验证，避免把规则修正当成纯换算：

| 阶段 | 产物 | 允许变化 | 完成标志 |
|---|---|---|---|
| A：等价迁移基线 | 整数单位、旧数据适配、可比较回放 | 表示方式改变；复刻旧取整、旧触发与旧上限 | 相同输入与随机事件下，归一化后的行动、触发、成长和胜负一致 |
| B：语义统一与反馈 | 文心／羁绊共用效果契约、明确单位、统一结算账单 | 本文登记的语义问题得到修正；允许细粒度整数取整 | 所有差异有原因编号；无未解释的重复发奖、漏发或错单位 |
| C：平衡与机制迭代 | 新增轻量成长、骰面简化表、档位曲线试验 | 每个试验单独变更 | 通过配对模拟、组合压力测试和真实试玩 |

正式新版以 B 为发布候选；A 是迁移比较工具，C 按试验结果逐项纳入。不能把 A 的“等价”宣传为 B／C 的平衡结论。

**本轮文档的四个关键决策：**

1. 文心的资源奖励必须写明目标资源。`value: 2` 不再能同时代表属性、心得、灵感和残页。
2. 胜／平／败的基础成长继续由心得、熟练和研修承担；当前成长类文心在新版默认对接心得，不恢复为无条件的直接属性暴涨。
3. 完整稿页、构思次数、研修位、骰点等离散对象不放大；“积累过程”和“完成后的物品／次数”是两个字段。
4. 终局分和战斗分使用不同单位。定卷的 60 终局分保持 60，不能因名字带 `score` 就乘十。

配套阅读：[全量文心与羁绊对接表](文心棋-数值重构-文心羁绊对接表-v1.md)。附表覆盖 49 枚主配置文心、12 枚支线文心、61 份升级配置和 48 组羁绊，包括每级效果的单位换算；它是设计对照表，不是可导入的正式配置。

## 3. 单位体系与换算边界

### 3.1 正式目标单位

| 单位 ID（建议） | 对象 | 换算 | 典型新值 |
|---|---|---|---|
| `attribute` | 六维、永久／临时属性、属性门槛与差距 | 旧值×10 | 初始 50，标准成长 10，流派 +30 |
| `inspiration` | 灵感、上限、价格、返还、绝对阈值 | 旧值×10 | 360／540，追加骰 50 |
| `insight` | 心得、容量、培养／转换消耗 | 旧值×10 | 胜／平 30，败 20，修习通常 40 |
| `study_progress` | 每个研修位的连续进度 | 旧值×1000 | 初始每场 1200，满 3000 兑现标准成长 |
| `manuscript_progress` | 原残页及其连续结转 | 旧值×1000 | 初始每战 250，满 2000 合成 1 稿页 |
| `strategy_progress` | 阶段构思收入与不足一次的余量 | 旧值×1000 | 初始每阶段 1500，每 1000 转 1 次 |
| `count` | 稿页、构思次数、槽位、等级、次数、回合、棋格、熟练和技法经验 | 不变 | 稿页 1、构思消耗 1、熟练满 3 |
| `pip` | 自然／最终骰点、点数和与点数阈值 | 不变 | 1～6，总点 12／16，7 的倍数 |
| `battle_score` | 作品分、NPC 固定分、战斗固定增减 | 旧值×10 | 初始底盘 110→1100 |
| `final_score` | 六维结算分、定卷分、评级门槛 | 保持旧量级 | 定卷 60，秀才 3000 |
| `bp` | 比例、概率、倍率与乘区 | 旧小数×10000 | 4%=400 bp；1.25 倍=12500 bp |

`bp` 是内部万分比整数；玩家看到“+8%”“八折”“保留一半”，不看到 bp。权重可以是独立整数权重，归一化时再计算概率；不把随机权重当作资源。

**对初步方案的细化修订：连续进度从百点制改为千点制。** 当属性允许新单位 +1（相当于旧 +0.1），学力每次带来的研修变化是旧 0.004。百点制仍产生 0.4 点进度，千点制可直接写成整数 +4。这样无需增加隐藏的 0.4／0.5 进度余量。界面通过进度条与“还差多少”减少四位数字的阅读负担。

### 3.2 不能按字段名批量乘十

例子：`comeback.threshold` 是灵感，乘十；`dice_pattern.tiers[].threshold` 是骰点和，不变；`armory_pct.step` 是文心数量，不变；`manuscript_pct.step` 是稿页数量，不变；`volumeScore` 是终局分，不变；`battleFormula.styleCommonMult=7` 是系数，不乘十。

`effect.value` 的单位必须由效果类型、目标资源和触发路径共同确定。未知字段中止迁移并列出路径，不能默认放大，也不能悄悄保留。

### 3.3 数值精度规则

1. 资源、进度、次数、已结算分数和公开配置用整数；比例用 bp；分式中间值用整数分子／分母，禁止把小数写入存档。
2. 阶段 A 保留旧取整边界。例如旧 `ceil(4×0.8)=4`，等价新费用是 40；不能误当成 32。
3. 阶段 B 支持新单位精度。上述费用可改为 `ceil(40×8000/10000)=32`，这是已标记的实际降价，需纳入经济校准。
4. 概率判定采用 `rInt ∈ [0,9999]`，命中条件 `rInt < chanceBp`。复刻旧随机流时使用专门适配，不能改变随机数消费次数。
5. 答题计时、音量、动画、几何坐标等不属于此次整数化对象；禁止对全部 JavaScript 小数做清零式替换。
6. 负向四舍五入明确为对称舍入：`sign(n) × floor(abs(n)/d + 0.5)`。A 的负数行为按旧实现单独保留；不能假设 JavaScript `Math.round` 的负半数与此相同。
7. 计算模块对 `NaN`、无穷、负费用和超出安全整数乘积的输入明确报错。用整数商余数或 BigInt 完成可能超范围的乘除，存档仍序列化十进制安全整数或显式字符串。

## 4. 六维成长与三功对接

### 4.1 属性与成长入口

初始诗／词／联／笔／学／思均为 50；博闻学力 +30、奇士思力 +30、辞宗笔力 +30。初始文心的常驻属性另算：例如博闻的 T004 Lv1 再提供学力 +30，因此其有效初始学力可达 110，不能只按 80 编制开局表。

| 收益／阈值 | 当前 | A 换算后 | B 规则 |
|---|---|---|---|
| 仄格属性收益 | 1 | 10 | 保留；实际按当前落格路径领取 |
| 直接答题配置收益 | 4 | 40 | 标为配置映射；柔性抉择／研修路径需按各自资源兑现，不额外叠领 |
| 名胜支线属性配置收益 | 5 | 50 | 仅迁移实际消费该字段的路径 |
| 实战熟练 | 每战 +1，满 3 兑 +1 属性 | 每战 +1，满 3 兑 +10 属性 | 熟练计数保持；允许未来另加明确进度奖励 |
| 心得修习 | 消耗 4 兑一次成长 | 消耗 40 兑标准成长 +10 | 所有按钮展示实际递减后的可得成长 |
| 追赶 | 差距 ≥6，消耗 3 | 差距 ≥60，消耗 30 | 原优先级保留，不能同时收取追赶价与专精价 |
| 专精 | 本体高于三体均值 ≥6，消耗 5 | 本体高于三体均值 ≥60，消耗 50 | 用 `3×本体−三体总和≥180` 判定，避免均值小数；追赶判断优先 |
| 递减档位 | 34／48 | 340／480 | A 原收益×10；B 才开放 +1～+9 的微成长 |

正向成长全部进入同一 `grantAttributeGrowth`（拟新增）入口。常驻文心属性属于来源加值，不套成长递减；否则升级／卸下会不可逆地改变基础属性。建议状态拆为 `baseAttrs + persistentSources + battleOnlySources`，存档清楚记录来源，传承只读取其规定的属性集合。

### 4.2 学力：研修与心得容量

令 X 为新单位学力，三功成长统一读取基础修为与常驻来源之和的快照，不计只用于本场算分的天象／百分比临时属性：

```text
每场每位研修进度 = min(2000, 1000 + 4X)
研修需求 = 3000
本次完成次数 = floor((旧进度 + 本次进度) / 3000)
结余 = (旧进度 + 本次进度) mod 3000
本次名义属性成长 = 完成次数 × 10
心得上限 = 60 + 10 × floor(X / 30)
研修位 = min(3, 1 + floor(X / 100) + 流派额外位 + 名篇额外位)
```

学力 50／100／160／200／250，研修收入分别 1200／1400／1640／1800／2000。学力 51 收入 1204，新增一点属性确有明确用途。

地图创作抉择原本增加研修 1，则改 +1000；`study_bonus` 文心不得仅因名字相似就乘 1000，它在目标三功路径中发的是心得，按×10 迁移。

收益先计入对应属性研修位，再按次数兑现成长；不得中途因学力刚升级就把本场其他研修位收入改用新学力。下场才使用新快照，防止遍历顺序改变收益。

### 4.3 思力：构思次数与蓄积

令 S 为新单位思力：

```text
阶段收入进度 = 1000 + 10S + 流派额外次数×1000
合计进度 = 上阶段结余 + 阶段收入 + 名篇开局次数×1000
本阶段生成次数 = floor(合计进度 / 1000)
不足一次的结余 = 合计进度 mod 1000
构思次数上限 = min(6, 3 + floor(S/100) + 流派上限加值 + 名篇上限加值)
```

当前 `refillStrategy` 是新阶段重设次数，不是把上阶段剩余次数相加。A／B 保留这一语义：未用次数在换阶段时不叠加，只有不足一次的进度结余保留；超出次数上限的整次收入溢出，不偷偷兑换灵感。界面提前显示换阶段规则。

| 章法 | 新规则 |
|---|---|
| 徐行拾句 | 自然移动骰 1～3，消耗 1 次构思，成稿进度 +1000；不能用指定移动骰冒充自然骰 |
| 留白养气 | 败北时消耗 1 次构思，减少 20 灵感败北额外损失；损失最低为 0 |
| 换韵生新 | 文体不同于上一场时消耗 1 次构思，作品修正 +600 bp（+6%） |

奇士的每阶段额外 1 次、上限额外 1 次、阶段首次章法免费均保持计数，不乘十。免费只免消耗，不额外增加次数，且同一阶段标记只消费一次。

### 4.4 笔力：成稿、稿页与定卷

令 B 为新单位笔力：

```text
每战被动成稿进度 = min(1500, 5B)
成稿需求 = B ≥160 ? 1000 : 2000
稿匣容量 = min(8, 2 + floor(B/60) + 流派额外容量)
```

基础结果稿页保持：获胜且最终一骰给 2 页，获胜多骰给 1 页，平局给 1 页，失败给 0 页但另加成稿进度 1000。文心进度与结果补偿加入后统一合成；稿页受稿匣上限限制。A 的动态门槛读取顺序照旧；B 在本场战后成长前锁定笔力快照，防止先结算研修就立即把本场合成需求减半。

| 稿页行动 | 当前 | 新版 |
|---|---|---|
| 润色 | 2 页，首枚追加骰减费 2 | 2 页，减费 20；辞宗首次少耗 1 页仍是 1 页 |
| 发表 | 3 页，灵感 +4 | 3 页，灵感 +40 |
| 定卷 | 5 页，终局 +60，最多 2 卷 | 数量、终局分均不变 |
| 成稿加速 | 笔力 16 | 笔力 160 |
| 阶段额外稿页门槛 | 笔力 24 | 笔力 240；一次性阶段标记不变 |
| 定卷返页 | 笔力 32，返 1 页 | 笔力 320，返 1 页 |

### 4.5 成长递减与微奖励

A 必须调用旧逻辑的等价整数适配，得到旧实际收益×10；不能把原来的逐点循环直接扩大为十倍迭代，并把最低收益改成 1 后宣称等价。

B 的目标是按“一个语义事件、同一属性”先合并成长来源，再过 340／480 的 100%／50%／25% 递减。跨档逐段计价，每段只按实际增长跨越阈值。最低保底改为每个正向成长事件 +1 新属性点；采用整数余量账本保留不足 1 点的递减收益，余量不得复制给多个来源。此规则改变原来“旧 +1 始终至少 +1”的效果，必须独立比较后期成长和传承。

具体使用四分之一属性点作为内部整数记账单位：新属性 340 对应 1360 个记账单位。每投入 1 个名义成长点，按当时属性加余量所在档获得 4／2／1 个记账单位；累积满 4 兑 1 点属性。整次语义事件结束后若仍不足 1 点而启用保底，则补足 1 点并清空这次不足一整点的余量，不能既保底又保留同一份余量。这会令非常小的高档奖励存在保底优势，因此同场同属性必须先合并，不允许拆成多个事件刷保底；是否保留该保底是 C 阶段可测试的独立参数。

试验奖励档：微小 +2、轻量 +5、标准 +10、显著 +20、里程碑 +30～50。它们是机制预算，不自动重写每个现有奖励。常驻属性、直接成长、研修进度和心得没有固定一比一价值，需按兑现延迟、容量和剩余战斗次数估算。

## 7. 羁绊系统

### 7.1 激活、条件与叠加

所有 48 组保持 ID 与成员关系；全成员持有才激活，持有相同 ID 的多个副本不算多个成员。等级不影响激活，除非某组将来明确增加等级门槛。A 保留当前组别；B 改为语义分组：

| 规则 | B 决策 |
|---|---|
| 不同来源、不同机制 | 默认可叠加，同属作品修正区加算 |
| 同一效果 ID 重复入队 | 去重，只结算一次 |
| 同一效果的等级档、总点档 | 取最高满足档 |
| 明确互斥的同类增强 | 显式 `exclusiveGroup`，同组取最大；不得把所有支线羁绊塞进一个组 |
| 得分与资源的组合奖励 | 各有 ID 与分组；得分被覆盖不代表资源自动保留或丢失，配置写明 |
| 负面修正 | 不用正向 max 分组过滤；按契约单独计入 |
| 次数限制 | 按稳定 sourceId／effectId＋局／阶段／战斗 ID 计数 |

## 8. 战斗公式、骰组与 NPC

### 8.1 保持作用层次，消除均值展示歧义

令 P／C／L 为新诗／词／联，W 为选中文体，B／X／S 为三功；D 为普通骰乘区 bp，M 为其他加算修正 bp，F 为固定战斗分，K 为终结倍率 bp。

```text
格律 = round((7×(P+C+L) + 9×W) / 3)
意象 = 4×(B+X)
立意 = 4×S
底盘 = 格律 + 意象 + 立意
骰分 = round(底盘×D / 10000)
基础作品 = 底盘 + 骰分
修正分 = round(基础作品×M / 10000) + F
最终作品 = max(0, round((基础作品+修正分)×K / 10000))
```

这是 B 的新单位精度公式。等价 A 在旧已取整的阶段按×10 复刻，不能直接用 B 的 round 替代。例如 A 的格律是 `10×round((7×(P+C+L)+9W)/30)`。玩家／NPC、预览／结算／模拟必须共用同一版本公式。

`attr_pct` 等六维算分属性效果在底盘前形成临时属性，`syn_pct` 等作品修正在 M 中；`lucky_six` 等明确终结倍率在 K 中。同层属性加成先合并；多个终结倍率保持当前取最高倍率的规则，不相乘。不得把 T026、S41、T024 全部当作作品修正相加。临时属性在 B 中保持整数分式中间值，进入各分项时才舍入，不写回永久属性。

明细展示“共通功底（按三体总值折算）+专精贡献”，不让玩家手算三体均值的小数。总分账单需包括终结倍率额外分；分项总和必须与最终作品一致。

平局判定以整数交叉相乘：`abs(我方－对方)×10000 <= max(双方)×500`。B 规定双方都是 0 时判平；旧 judgeBattle 对双零会返回 lose，因此这是边界语义修正，A 必须复刻旧结果。没有 ±1 的隐藏修正。

核对例（六维均为旧 5／新 50，无流派、文心、亲和、其他修正）：诗的一骰 1～6 的旧作品依次为 114、117、121、132、138、143；A 对应 1140、1170、1210、1320、1380、1430；B 按更细的整数精度为 1137、1175、1212、1320、1375、1430。这个差异来自取整粒度，不能误报为配置漏乘十。

### 8.2 骰面表与试验边界

普通骰基础为每点 400 bp；额外骰的独立加成与普通骰总点贡献分别核算，不能删掉其中一份，亦不能把同一份加两次。

| 诗的一骰点数 | A／B 保留 bp | 玩家旧精度百分比 | C 简化表（候选） |
|---|---:|---:|---:|
| 1 | 340 | 3.4% | 3% |
| 2 | 680 | 6.8% | 7% |
| 3 | 1020 | 10.2% | 10% |
| 4 | 2000 | 20% | 20% |
| 5 | 2500 | 25% | 25% |
| 6 | 3000 | 30% | 30% |

B 主界面优先显示“灵感骰实际 +N 分”，细节仍能查准确百分比，不把 3.4%伪装成 3%。C 简化表改变强度，必须作为规则更新；此处不将它写入迁移基线。

词首骰达到 5 的 +8%、联换体 +8%、词首追加骰减费 10 都保持。诗多骰不应误用“一骰一气”表；骰点加值导致超过 6 的兼容路径必须有扩展规则，不能无条件取六面表最后一项。

自然骰 `rawDicePips`、最终骰 `dicePips`、购买记录和主动操作记录分开存档／回放。低开判断读自然首骰；六点／对子等读最终骰，具体规则由效果契约声明，复制和改骰都不改写自然记录。

### 8.3 NPC、招牌与破绽

- 普通 NPC、阶段守关、支线 NPC、支线内嵌 NPC、殿试与隐藏对手的六维全部×10；同一 NPC 多处副本应统一从 ID 引用或由生成器同步。
- 招牌固定加分、固定扣分、对照战力和固定骰分×10；百分比、削弱保留率和借取比例转 bp；骰点／阶段／权重不按十倍放大。
- 破绽顺序：读取公开选择 → 判断是否命中 → 得到招牌保留率 → 计算残余固定／比例效果 → 形成双方作品明细。保留率只施加一次。
- TA09 封印、TA02 借取、T011 亲和转化和主动改骰分别指定作用对象；禁止把已经削弱后的比例再次乘一次保留率。
- 先比较同 NPC、同文体、同骰序列，再看全局胜率；NPC 选择器的“最低可接受战力比例”仍是比例，不能乘十。
- 难度辅助、新手首局补偿、阶段强弱倍率和隐藏殿试门槛一起迁移。单场殿试结构保持，旧脚本中多场殿试假设不得沿用。
- 玩家与 NPC 的联体解锁硬编码 8→80；任何按属性判断的隐藏对手入场条件、雷达图上界与条件文案同步转换。主方案中的全部三体公式不代表开局已解锁全部文体。

## 9. 统一结算顺序与回响

### 9.1 目标战斗生命周期

1. 开战：应用已提交的战前消费，锁定六维、稿页、阶段、历史和可用文心等级；生成 battleId。
2. 操作：自然骰、续掷、主动文心逐操作验证并支付；记录原始与最终骰、购买次数、实际费用。预览纯计算。
3. 定稿：冻结最终触发条件快照；绝境条件默认读取实际支付后、战后回复前的灵感。标注其他明确读取时点的效果。
4. 算分：NPC 招牌／破绽、属性乘区、普通骰、作品修正、终结倍率；只生成得分和奖励意图，不立即发资源。
5. 判定：胜／平／败、越级和战绩，由同一结果快照驱动。
6. 战后损失：结算尚未支付的规则费用、败北额外损失、章法减损、天象奖惩；已支付的入场费不可重扣。
7. 固定结果奖励：发放胜利回复、骰组／破绽奖励、心得；容量在此步进入前锁定。按资源合并后截断，同源不递归。
8. 成长：熟练、研修、成稿按开战锁定三功结算，文心额外进度合并；兑现属性与稿页；额外容量从下一次资源事件开始生效。
9. 低灵感恢复：以第 8 步结束的灵感为统一快照，判定各低灵感奖励的资格，一次性合并；最后执行底线补足。这是目标规则，需与旧顺序单独比较。
10. 后续效果：登记“下一战加成”、更新历史、掉落与选择结果、执行阶段完成逻辑；最后写入已结算标记和存档。

异步选择界面可暂停步骤 10，但不能重新执行步骤 6～9。重载读取事务阶段，从尚未完成的步骤继续。战后结算入口再次调用，返回同一账单，不再发奖。

## 10. 地图、流派、天象、事件与名篇

### 10.1 三流派

| 博闻 | 研修位 +1、知识计数、求心尝试次数 | 知识奖励心得 4→40，换体心得 2→20，求心费用 8→80 | 心得在培养和求心之间竞争；上限变化不能重发被截断的旧奖励 |

| 辞宗 | 稿匣 +1、阶段额外页、首次润色少耗 1 页、求心 3 页 | 笔力开局加成×10，相关灵感收益×10 | 定卷、发表、润色、求心共用稿页，不能重复扣／免费重复使用 |

掉落概率、概率上限和保底胜场分别是 bp 与次数。当前代码中的保底常量与配置是否一致必须单列核查，数值迁移不把未被读取的配置当成已生效规则。

### 10.2 地图与事件

对 `board`、`events`、`questions`、`sidequests`、`narrative` 建字段清单：属性／灵感／心得×10，连续进度×1000；前进格数、停留回合、路线选择、题目正确性、关系遭遇数保持；`nextBattlePct` 转 bp。

事件在选项点击前展示真实成本与收益。输入非法、资源不足、选择取消时不扣资源；收益含随机分支时先锁定选项再消费对应随机事件，不为展示重新抽取。支线取舍的叙事方向、专属文心 ID 和结局记录保持。

名胜的配置收益、支线 act 效果与原地图落格奖励可能走不同路径，需要逐入口标注是否替代／叠加，不能因都有 +50 就发两次。

### 10.3 天象与亲和

天象的灵感奖惩倍数转倍率 bp，但次数和持续回合不变；“科场风起”的奖惩翻倍不应扩大到属性或所有文心收益。作用域由 `resource + reason` 显式控制。

亲和矩阵、主场加成、时代题材／文风、气势每层与上限按比例／层数分开；`experimentalManner` 当前随机范围 -12%～20%，用 -1200～2000 bp，以 100 bp 为步长保持现有整百分比抽样。不能变成每 1 bp 抽样而悄悄改变分布。

T011 的复制比例作用于亲和，不作用于总作品；T022 放大气势；NPC 偏好权重保持独立。来源应在账单中明确，避免多个系统都写“加成 10%”却无法说明基数。

### 10.4 名篇与跨局成长

`album.json` 中 `trigger=start/battle/score` 的奖励按目标资源转换：属性／灵感／inspirationMax／insight×10；manuscript 稿页、strategy 构思、studySlot／strategyCap 等次数／槽位保持；作品／殿试加成用 bp。名篇经验、等级、解锁次数和携带槽不扩大。

名篇提供的临时属性、开局资源与文心常驻属性应分别保留来源。教学局继续不写正式跨局战绩、评级和奖励，不能因加入新 numericVersion 使教学记录被当正式记录。

## 11. 终局评级与跨局传承

### 11.1 终局保持量级

终局评级不直接使用十倍后的属性和灵感套旧系数。令三体之和为 C、三功之和为 G，均为新属性单位：

```text
文采基础分 = round((12×min(C,510) + 6×max(0,C-510)) / 10)
功力基础分 = round((10×min(G,390) + 5×max(0,G-390)) / 10)
剩余灵感得分 = round(15×新灵感 / 10)
```

只在原维度结算位置取整，不先把每个新属性除以十向下取整。这样新 +5 属性可产生应有贡献。条件阈值按单位迁移：三绝均衡 24→240、破壁 22→220、根基极差≤2→≤20、偏锋 20→200、宗师单体 30→300、三绝 18→180、从容剩余灵感 6→60；胜场 3、回合 48／50 不变。

战绩、奇遇、名篇／文心数量加分、定卷分、抵达分以及各评级分段保持旧量级。评级结果另带 `scoreRulesVersion`，禁止把新版更强的机制得分与旧榜默认混排。

A 必须复刻原终局取整与各维上限；B 使用新精度之后，即使门槛未改，也要重新量测评级分布。文宗 4300 的原历史模拟说明不能作为当前重构已验证的证据。

### 11.2 照我传灯

T034 的门槛 40→400、初始灵感 8→80、继承率 0.8→8000 bp；各升级档以附表为准。A 新继承属性为“旧向下取整结果×10”；B 为 `floor(新属性×继承率Bp/10000)`，精细保留更多修为，必须单独测试多代增长。

传承存储 `feihua_reincarnate_v1` 有独立读取入口，要带数值版本。待领取继承属性只转换一次；文心 ID／等级不变；尚未消费的传承、已经消费后进入的对局、重复开局请求分别检查幂等。

目标传承属性集合需明确：基础修为与允许继承的永久成长可继承；不能把当前装备的常驻来源加值继承后又在下局因文心存在再次免费复制。A 保留原行为，B 若改集合需在迁移说明中明示，不能从旧总属性逆推出不存在的来源明细。

## 12. 配置、编辑器与内容同步

### 12.1 数值版本契约

建议新增独立元数据，不复用 `_version` 或现有 abilitySystem.version：

```json
{
  "numericVersion": 2,
  "effectSchemaVersion": 2,
  "scoreRulesVersion": "numeric-v2",
  "balanceRevision": "baseline-1",

    "attribute": 10,
    "inspiration": 10,

  }

```

以上为目标格式示意，尚非现有加载器支持字段。`numericVersion` 决定单位，`effectSchemaVersion` 决定效果结构，`balanceRevision` 标记同单位调参，内容 `_version` 只管发布新旧次序。

### 12.2 单一权威与编辑器要求

- 本地正式 `config/*.json` 为迁移源，统一生成编辑器 seed 和根 `feihua-content.json`；不手动维护三份数值。
- 更新 `config-contract.js` 与编辑器 `feihua-contract.js` 的同源契约，禁止一个允许 bp、另一个仍把输入“8”解释为 800%。

- 文心升级必须显示完整等级差异，支线升级数据与主升级数据同样校验；没有升级配置时不得默默拼出默认高等级。
- 描述从结构生成关键规则段，文学引文与氛围文本单独保留。叙述中的“+2”“最多三次”也纳入一致性检查。
- `config-dev` 与代码 fallback 同步单位；未知版本明确报错，不回退到旧单位默认值继续开局。

- 同步脚本当前有硬编码根路径，实施时以脚本位置定位仓库；生成前做版本兼容检查，生成后做逐内容相等检查。

## 13. 存档迁移与回退

当前主运行存档版本常量是 9，含自动、手动、教学槽；不直接把 v9 改名当作数值 v2。实施时预留新的运行存档版本，并独立写入 `numericVersion`，具体整数版本要与当时代码确认，避免占用已发布版本。

### 13.1 迁移清单

| 状态 | 处理 |
|---|---|
| attrs、inspiration、inspirationMax、insight 与绝对上限 | ×10 |
| 研修 progress、manuscript.fragments、strategy.chargeRemainder | ×1000；原小数按旧允许精度解析，只在入口换算一次 |

| 持有文心、升级副本与来源加值账本 | ID／等级重建目标配置，迁移来源已应用标记，不能再重复加属性 |

### 13.2 原子迁移流程

读取原档并保留只读副本 → 校验旧版本与结构 → 迁移到临时新槽 → 校验整数、不变量、容量、ID 引用和来源重复 → 读回临时槽验证 → 设置当前版本指针 → 原档继续保留。

同一原档指纹迁移两次必须得到相同结果；失败保留原指针与原档并给出具体原因。损坏、未知版本、跨版本内容缺失时不能假装迁移成功。旧小数如 1.6400000000000001 按已知旧单位规范化为 1640，不把二进制噪声转成巨大整数。

阶段 A 可以验证进行中战斗的状态转换；B 上线的默认策略是让进行中的旧局继续使用旧规则快照，结束后新局启用新规则。确需中途转新版时仅在地图安全点迁移，不能在已支付主动效果、未结算的战斗中切换语义。配置快照需固定，不能只写一个版本号却仍读最新云数据。

### 13.3 回退

代码从不可变备份标签创建恢复分支，配置与编辑器内容使用同一版本包。客户端回退到旧规则时读取保留的旧槽；新版档不进行有损除十后覆盖旧档。新版局已经产生的等级、成就等外部写入不能仅靠代码回退撤销，需要记录版本和提交事务，避免二次写入。

排行榜按版本分榜或明确筛选规则，不批量覆盖历史成绩。多人客户端版本不匹配时在入局前拒绝连接，不允许一方 36、一方 360 共用会话。

### 14.2 配对模拟

使用现引擎构建有版本的测试适配，保留事件流而非仅保留一个 seed：随机调用结构一旦改变，同一个 seed 不保证遇到同一个对手／骰子。分别记录地图、事件、NPC、骰子、掉落和玩家选择流。

先跑可穷举的小集合：标准三枚 d6 的有序骰面共 216 组；将一骰、二骰、三骰、改骰与各级文心纳入。再跑完整对局：建议每个“3 流派×3 玩家策略档”至少 1000 个配对事件流，总计至少 9000 对，样本不足时不得写精确到小数点后的胜率结论。

策略档应是可复现的实际决策策略：基础随机／按明确规则选择／资源与构筑策略。不要只用“答题正确率 0.75”冒充完整玩家行为。另设纯一骰、多骰、低灵感、稿本、换体、殿试集中、三代／十代传承压力场景。

| 阶段 | 验收要求 |
|---|---|
| A | 按各自单位归一化后事件结果、资源支付次数、触发次数、成长兑现、评级及胜负全等；任何差异必须归因，不能用总体胜率接近替代 |
| B | 无非整数状态、无重复发奖、无未登记差异；SEM 修正前后分别报告收益与翻转；通关率／中位终局分偏移超过预设预算则返工 |
| C | 单变量或可区分的试验分支；报告分布、置信区间、构筑选择和失败原因，不能仅给平均战力 |

B 的首轮警戒线建议：同策略通关率变化超过 3 个百分点，或归一化终局分中位数变化超过 5%，即触发重新校准；这是评审预算，不是已验证结果，也不允许以“未超线”忽略某流派／组合被破坏。

必须输出：各阶段有效属性 P10／P50／P90、剩余灵感、每局追加骰数、主动／升级支出、心得溢出、稿页产消与溢出、构思未用次数、文心触发率、羁绊同时激活数、NPC 胜率、平局率、完局回合、封笔率、评级分布、继承代际增长。

### 14.3 真实试玩

至少覆盖新玩家与熟悉玩家，每人先体验旧版与新版中的一版，再交叉体验，避免固定顺序偏差。重点观察玩家能否在不展开公式的情况下说明：本次多得了什么、下一次收益还差多少、续掷真实代价、文心是否触发、升级改变了什么。

记录理解错误和决策耗时，尤其是千点进度是否造成阅读负担。若负担偏高，先改信息层级与进度条，不能仅把 1640 四舍五入展示为“2 次成长”。小规模试玩用于可读性诊断，不用于宣称某构筑胜率已稳定。
