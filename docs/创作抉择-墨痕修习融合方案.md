# 飞花棋｜创作抉择“墨痕—修习”融合方案

> 版本：1.0
>
> 用途：交给后续执行窗口实施的设计交接文档
>
> 范围：创作抉择题、三功修习、即时反馈、阶段评语与终局回声
>
> 本文只定义设计与验收标准，本次不包含代码实现。

## 1. 设计结论

不要把“墨痕”做成独立货币、素材库存或新的战斗按钮。

采用以下职责分离：

- **修习**负责数值成长：心得、研修进度、属性兑现。
- **墨痕**负责成长来源与叙事记忆：玩家为什么获得这次成长，以及后续文案如何引用它。
- 创作抉择只产生一次“修习单位”，不再直接给诗力、词力、联力等属性大额加成。

核心循环为：

```text
创作抉择 → 选择即时回声 → 修习进度/心得 → 属性成长 → 阶段与终局引用墨痕
```

目标是让玩家感到“我的选择塑造了我的写法”，同时不增加第二套需要管理的资源系统。

## 2. 当前问题

当前创作抉择题主要存在四个问题：

1. 选项通常直接给属性加成，容易继续强化当前最高文体。
2. 第三项经常是 `attr: null`，形成无收益选项。
3. 选择结果没有进入修习系统，玩家看不到它如何改变成长。
4. 创作抉择没有短程、跨阶段或终局反馈，选完即结束。

当前三功修习已经具备可复用的成长骨架：

- 心得：可在修习面板自由分配。
- 研修位：锁定若干属性方向，论战后自动推进进度。
- 进度阈值：达到 `progressNeed` 后自动兑现属性。
- 学力、思力、笔力已经分别承担研修、筹策、稿本等不同职责。

因此本方案不新增资源，而是让创作抉择接入现有心得与研修进度。

## 3. 创作抉择的新规则

### 3.1 每个选项必须有修习方向

将原来的：

```text
option.attr
```

改为设计意义上的：

```text
option.studyTarget
```

可用方向为：

```text
shi / ci / lian / bi / xue / si
诗力 / 词力 / 联力 / 笔力 / 学力 / 思力
```

方向不是“正确答案”，而是玩家此刻选择练习哪一种能力。

### 3.2 选项与修习方向的映射

| 选项表达 | 建议方向 | 设计含义 |
|---|---|---|
| 引用、化用、按既有体式完成 | 诗力 / 词力 / 联力 | 借传统成篇 |
| 查证出处、接受指点、守住规范 | 学力 | 扩充与校正知识 |
| 追问意义、改变视角、重新立意 | 思力 | 把景物转成判断 |
| 自写、炼字、修改、捕捉细节 | 笔力 | 把感受落成自己的句子 |

每道题的三个选项至少覆盖两个不同方向，禁止三个选项全部指向同一属性。

### 3.3 修习收益结算

每次有效选择只产生一个修习单位。

#### 选择当前研修方向

若 `studyTarget` 在当前生效的研修位中：

```text
对应 study.progress +1
```

达到现有 `progressNeed` 后，沿用现有逻辑自动兑现对应属性 `+1`。

示例：

```text
墨痕·问月：与你当前的思力研修相合，思力进度 2/3。
```

#### 选择非当前研修方向

若 `studyTarget` 不在当前研修位中：

```text
心得 +1
```

心得仍由现有“修习”面板自由分配，玩家不会因为选择了非当前方向而没有收益。

示例：

```text
墨痕·自写：这次体悟暂未入当前课业，化为心得 +1。
```

#### 心得已满时的兜底

如果心得已经达到上限，非当前方向的 `心得 +1` 自动转为该 `studyTarget` 的研修进度 `+1`。

```text
心得已满，这次体悟转入笔力研修，进度 1/3。
```

这样所有有效选项都不会产生“选了但什么也没得到”的情况。

### 3.4 不再直接给属性大额奖励

创作抉择不再使用当前的直接属性奖励，例如：

```text
诗力 +4
思力 +4
```

最终属性只能通过现有两条路径产生：

- 研修进度达到阈值；
- 玩家在修习面板消耗心得。

这样可以避免创作抉择继续强化“最高属性 → 继续选同属性”的正反馈。

## 4. 第三选项的内容规范

第三项不能再只是“不做事”“抄现成”或“继续赶路”。它应代表一种成立的创作态度，通常对应“观察、自写、留白、休息后再写”。

例如“月下独酌”：

| 选项 | 修习方向 | 墨痕倾向 |
|---|---|---|
| 举杯邀月，把孤独写成三人共饮 | 诗力 | 出新、独行 |
| 追问江月何年照人 | 思力 | 求真、独行 |
| 不借古句，先记下江面碎光，归后自写一行 | 笔力 | 求真、惜身 |

第三项不代表“较差的选择”，而是代表不立即借用古人答案、保留自己的观察。

## 5. 墨痕的职责

墨痕不是资源，不显示数量，不占容量，也不能主动消耗。

每次选择只记录：

```text
questionId
optionIndex
studyTarget
resultText
inkTags: 1—2 个叙事倾向
```

叙事倾向沿用剧情设计文档中的四条轴线：

- 逐名 ↔ 求真
- 守法 ↔ 出新
- 与人 ↔ 独行
- 惜身 ↔ 燃笔

这些倾向不直接改变战斗分数，不用于揭示 NPC 内部信息，也不替玩家判定“正确价值观”。

## 6. 反馈层级

### 6.1 即时反馈

复用现有答题结果界面，不增加额外弹窗：

```text
你没有借用古人的月亮，只记下水上的碎光。

墨痕·自写：笔力研修进度 +1。
```

结果页必须同时显示：

- 选择后的 `resultText`；
- 本次修习方向；
- 实际获得的心得或进度变化。

### 6.2 成长兑现反馈

当研修进度达到阈值时，引用最近相关的墨痕：

```text
江畔记下的碎月终于落入笔端。
笔力研修完成：笔力 +1。
```

### 6.3 阶段反馈

在已有换圈或阶段结算界面增加一小段“行卷评语”，不新增独立操作：

```text
本阶段行卷：你多次绕开现成名句，宁愿先看清眼前之物。
```

评语从本阶段的选择记录中选取，不显示道德数值。

### 6.4 终局反馈

殿试评语、普通结局和隐藏终圈结局各引用一次具有代表性的选择：

```text
王侍郎翻到你江畔留下的旧页：
“不肯借句，不等于无所本；这一笔，终于像你自己。”
```

## 7. 数据约定

执行窗口可以在现有题目结构上增量增加字段：

```json
{
  "text": "不借古句，先记下江面碎光，归后自写一行",
  "studyTarget": "bi",
  "inkTags": ["求真", "惜身"],
  "resultText": "你没有急着借用前人的月色……"
}
```

兼容规则：

- 旧题缺少 `studyTarget` 时，可按原 `attr` 映射。
- 旧题 `attr: null` 必须由内容编辑补上方向，不能继续作为空奖励保留。
- 旧存档不需要补发历史墨痕。
- `choiceHistory` 可以只保存题目 ID、选项序号和方向，不需要保存独立资源库存。
- 不改动现有心得、研修位、研修阈值和修习面板的基本操作。

## 8. UI调整范围

### 创作抉择结果页

增加一行统一的收益反馈：

```text
修习所得：思力研修进度 +1
```

或：

```text
修习所得：心得 +1
```

### 三功修习面板

不增加“墨痕”资源区，只增加一段最近记录：

```text
最近一笔：问月（思力）·“你选择先追问，再落笔。”
```

最多显示最近3条，避免面板变成日志浏览器。

### HUD

不增加常驻墨痕计数，不增加新的按钮，不增加每回合弹窗。

## 9. 实施顺序

### 第一阶段：规则接入

1. 为题目选项补充 `studyTarget`、`inkTags`、`resultText`。
2. 将创作抉择的直接属性奖励改为“当前研修进度 +1 / 非当前研修心得 +1”。
3. 增加心得已满时的进度转换兜底。
4. 保留现有超时惩罚与答案题、创作抉择题的区分。

### 第二阶段：即时反馈

1. 在答题结果页展示 `resultText`。
2. 展示实际修习收益。
3. 在日志中记录一次墨痕来源。

### 第三阶段：阶段与终局回声

1. 保存本局的选择记录。
2. 阶段结算显示一条行卷评语。
3. 殿试、普通结局与隐藏终圈结局各增加一次墨痕引用。

### 不在本次实施范围内

- 独立文料库存；
- 新增墨痕货币或容量；
- 战前文料选择；
- 墨痕兑换技能；
- 根据墨痕揭示 NPC 意图、未来骰面或地图信息；
- 让墨痕直接增加最终分数。

## 10. 验收标准

### 规则验收

- 每个有效创作抉择选项都有收益。
- 不再存在因 `attr: null` 而产生的空奖励选项。
- 创作抉择不再直接大额增加文体属性。
- 当前研修方向与非当前方向的收益都不会被容量或状态吞掉。
- 心得、研修进度和属性兑现仍遵循原有阈值与成本。

### 反馈验收

- 每次选择后，结果页能看见具体文案和具体收益。
- 研修完成时，至少有一条来源于创作抉择的解释文本。
- 每阶段最多展示一条综合行卷评语。
- 终局能引用至少一条本局创作抉择。
- 不增加每回合交互弹窗。

### 平衡验收

- 选项选择率不应长期集中在单一修习方向。
- 选择非当前研修方向时，玩家仍能感到收益明确。
- 创作抉择不应成为单局属性成长的主要来源。
- 墨痕不改变 NPC 信息可见性，不读取隐藏答案或内部胜率。

## 11. 最终判断

本方案把“墨痕”从一个可能继续膨胀的新系统，收敛为修习系统的来源记录层：

```text
修习是机制，墨痕是解释；
心得是资源，研修是兑现；
创作抉择决定方向，阶段与终局负责记住它。
```

这样既能解决创作抉择“没有收益、没有后续反馈”的问题，也不会再引入新的库存、消耗、弹窗和复杂操作。
