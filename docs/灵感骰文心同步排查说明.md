# 《文心棋》灵感骰文心不同步排查说明

更新日期：2026-08-28

## 结论

本次灵感骰文心改动已经发布到线上游戏与线上编辑器的静态文件中；问题不在部署遗漏，而在浏览器本地保存的旧工作区 / 自定义工程配置优先级高于线上默认数据。

线上已核验的配置包括：

- `T005 急智`：`low_then_high`（低开高走）。
- `T010 天马行空`：`all_distinct`（三骰各异）。
- `T016 文思泉涌`：`ascending`（逐骰递升）。
- `TA01 七步成诗`：`exact_total`（合计七点、首枚续掷免费）。
- `TA05 一气呵成`：`extra_dice_chain`（自动续章，不额外弹窗）。
- `TA06 倚马可待`：`total_tiers`（总点分档）。
- `T007 梦笔生花`、`TA04 笔落惊风雨`：保持原效果不变。

## 不同步原因

### 编辑器：旧的本地文心覆盖新版种子

编辑器启动时优先读取浏览器 `localStorage` 中的 `feihua_editors_v1_talents`。只有本地没有文心数据时，才会完整采用 `seed-talents.js` 中的线上默认种子。

当前“补齐官方文心”的逻辑仅处理缺失 ID，并明确不覆盖同 ID 的本地修改。因此已经在本地保存过的 `T005`、`T010`、`T016`、`TA01`、`TA05`、`TA06` 等旧条目，会持续显示旧效果；即使线上种子已更新也是如此。

这项行为原本用于保护编辑者的自定义内容，但对于官方同 ID 的机制迁移，会形成“发布已成功、编辑器界面仍旧”的错觉。

### 游戏：本地自定义工程可以覆盖线上默认配置

游戏加载时允许 `feihua_custom_config` 与 `feihua_cloud_config_url` 等本地设置覆盖仓库内的默认 `config/talents.json`。如果曾从编辑器发布过工程、导入过配置或使用过云端工程地址，游戏就可能继续读取旧工程中的文心档，而不是最新线上游戏配置。

另外，已经开始的对局会保留本局已经获得的文心对象；刷新默认配置不会倒灌改写进行中的局。

## 当前线上状态

2026-08-28 复核结果：

- GitHub Pages 构建状态为 `built`。
- 游戏 `config/talents.json` 返回新版骰组机制字段。
- 编辑器 `seed-talents.js` 返回同一批新版字段。
- 编辑器 `talent.js` 已具备 `low_then_high` 与 `extra_dice_chain` 的编辑支持。

因此，线上文件本身已经同步；需要处理的是客户端持久化数据的覆盖关系。

## 建议的修复方案

### 方案 A：官方文心增加版本迁移（推荐）

为官方文心种子增加 `officialVersion`，并在编辑器本地数据记录最近同步版本。

- 当官方版本升级时，仅更新官方 ID 的基础效果、文案与升级表。
- 将本地编辑内容保留在单独的覆盖字段或“自定义副本”中。
- 对发生覆盖的官方文心，在界面中显示“已同步至官方版本 / 保留本地版本”的状态与恢复入口。

这样既不会静默覆盖用户自建文心，也不会让同 ID 的旧官方数据永久遮住新版。

### 方案 B：为工作区提供显式同步操作（短期可落地）

在编辑器的工作区管理区新增：

- `同步官方文心`：仅替换官方 ID，保留用户自建 ID。
- `预览差异`：逐条显示本地与线上在名称、文案、效果、升级表上的差异。
- `保留本地版本`：对单条文心跳过同步，并记录该选择。

同步完成后，将对应的 `talent-upgrade` 一并更新，避免基础效果和升级表来自不同版本。

### 方案 C：游戏启动时提示自定义工程覆盖

若检测到 `feihua_custom_config` 或云端工程地址，游戏主菜单应清晰提示：

> 当前正在使用本地 / 云端自定义工程，可能不是官方最新版。

并提供：`继续使用工程`、`切换至官方最新版`、`查看配置来源` 三个操作。进行中的对局不强制热更新，只对新开局生效。

## 临时验证与恢复方式

在正式加入迁移机制前，可按以下方式确认新版：

1. 编辑器导出当前本地工作区后备份。
2. 清除该站点的本地存储，或使用无痕窗口打开线上编辑器。
3. 游戏中清除自定义工程配置后重新打开页面，并新开一局。
4. 检查 `急智` 是否显示“首骰 1—2 后续骰 5—6”的低开高走描述，以及“一气呵成”是否显示自动续骰。

> 注意：清除站点数据会删除未导出的本地编辑内容，因此必须先导出备份。

## 后续实施建议

优先实现方案 B，再以方案 A 固化版本迁移。这样可以先给编辑者可控的同步入口，随后彻底消除“官方更新与本地工作区互相遮蔽”的歧义。
